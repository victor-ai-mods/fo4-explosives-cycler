# Explosives Cycler — план реализации

Рабочее название по-русски — «Переключатель взрывчатки». Папка: `fo4-explosives-cycler`,
репозиторий: `github.com/victor-ai-mods/fo4-explosives-cycler`, плагин `ExplosivesCycler.esp`,
префикс EditorID и скриптов — `EXC`. Лицензия — The Unlicense.

Идея взята у Explosives Swap Hotkeys (`ESH.dll`, F4SE-плагин): гранаты и мины собраны в
списки, при броске последнего предмета автоматически берётся следующий. Отличия: списки
лежат в JSON-файле (до 10 штук), одна клавиша перебирает их по кругу, есть предмет в
инвентаре, делающий то же самое, и уведомление «Предмет (метка списка)». Мод на Papyrus + esp,
без своей DLL.

## 1. Что видит игрок

- **Клавиша** (задаётся в MCM) или **предмет мода** в разделе «Помощь» переключают
  текущий список на следующий по кругу: 1 → 2 → … → N → 1. Списки, в которых у игрока
  сейчас ничего нет, пропускаются. В новом списке экипируется первый предмет по порядку
  из тех, что есть в инвентаре.
- Отдельные клавиши MCM (по умолчанию не назначены): **«Предыдущий список»** — тот же
  перебор в обратную сторону (N → … → 1 → N); **«Следующий предмет в текущем списке»** и
  **«Предыдущий предмет в текущем списке»** — перебор по кругу только среди предметов
  текущего списка, которые есть в инвентаре; список при этом не меняется.
- На экране появляется `Debug.Notification("X, Y")`: X — название списка
  («Слабые гранаты»), Y — название предмета из игры («Осколочная граната»).
- **Предмет закончился** (брошен последний) → экипируется следующий по порядку предмет
  того же списка, который есть в инвентаре (после конца списка поиск идёт с начала).
  Показывается такое же уведомление «X, Y».
- Если во всех списках пусто, выводится «Нет взрывчатки из списков». Если пуст текущий
  список (кончился последний предмет, или нажата клавиша предмета), выводится
  «X: закончились», и мод **останавливается**: на другой список сам не переходит
  (решение пользователя).

## 2. Списки по умолчанию

Урон — `EXPL.DATA.Damage` взрыва гранаты (скан `tools/scan_explosives.py` →
`data/explosives.json`, ваниль + 6 DLC). Предметы с уроном только через зачарование или
дочерние снаряды (импульсные, MIRV, Lucky Rabbit's Foot) пока расставлены по вики, **в шаге 1 их
урон нужно досчитать** из `ENCH`/`MGEF` и дочерних `PROJ`/`EXPL`. При равном уроне
предметы сортируются по цене.

| # | Название (ru / en) | Состав |
|---|---|---|
| 1 | Слабые гранаты / Weak grenades | гранаты по возрастанию урона, без коктейля Молотова |
| 2 | Слабые мины / Weak mines | мины по возрастанию урона |
| 3 | Мощные гранаты / Strong grenades | гранаты по убыванию урона, без коктейля Молотова |
| 4 | Мощные мины / Strong mines | мины по убыванию урона |
| 5 | Коктейль Молотова / Molotov cocktail | `Fallout4.esm\|10C3C6` |

Черновой состав (урон взрыва):

- **Гранаты:** из бейсбольного мяча (100), криогенная (100), импульсная (зачарование),
  осколочная (150), «умная» осколочная DLC04 (150), плазменная (150), MIRV DLC04
  (дочерние снаряды), с «Ядер-Вишней» DLC04 (200), Молотов-кола (300 + огонь), с «Квантовой
  Ядер-Колой» DLC04 (300). Молотов-кола (`nukaGrenade`) — это не коктейль Молотова, она
  остаётся в гранатах.
- **Мины:** импульсная (зачарование) и её вариант из Automatron, осколочная (100),
  криомина (100), плазменная (150), крышко-мина (300), ядерная (300).
- **Не входят** капканы и шипы Far Harbor (`DLC03_Throwing*`), хотя движок считает их
  минами (решение пользователя).
- **Не входят** (урона нет, это служебные предметы): маяки синтов и Института, сигнальная
  шашка винтокрыла, артиллерийская дымовая шашка, «ГаллюциГен», DLC04 «Ярость»,
  «Хищник», «Убеждение». Не входят и неиграбельные записи (бомба Либерти Прайма, валуны
  Бегемота, гранаты NPC).

Игрок может сам собрать себе список, например из служебных гранат, в своём файле.

## 3. Формат JSON

Файлы лежат в `Data\ExplosivesCycler\`: `lists-default.json` (идёт с модом, обновление
его перезаписывает) и необязательный `lists-user.json`. **Если есть пользовательский файл,
он полностью заменяет стандартный**: сливать упорядоченные списки было бы непонятно.
Файл читается `GardenOfEden2.GetLinesFromFile` построчно, как исключения в Survival
AutoMedic. Поэтому у формата жёсткие правила: одна пара ключ-значение на строке, один
предмет на строке. Это настоящий JSON, но полноценный JSON-парсер не нужен.

```json
{
    "_comment": "Explosives Cycler: up to 10 lists, cycled in this order.",
    "_comment": "Item format as in LootMan: Plugin.esm|LocalHexID, one per line. Missing plugins are skipped.",
    "lists": [
        {
            "name_en": "Weak grenades",
            "name_ru": "Слабые гранаты",
            "items": [
                "Fallout4.esm|107BD6",
                "Fallout4.esm|0FF21D",
                "Fallout4.esm|0EEBED"
            ]
        },
        {
            "name_en": "Molotov cocktail",
            "name_ru": "Коктейль Молотова",
            "items": [
                "Fallout4.esm|10C3C6"
            ]
        }
    ]
}
```

Парсер — конечный автомат по строкам. `{` внутри `lists` открывает список,
`"name_<язык>":` задаёт название, строка вида `"Файл|ID"` добавляет предмет, `]` закрывает
`items`. Название выбирается по `sLanguage` (`Utility.GetINIString("sLanguage:General")`),
затем берётся `name_en`, затем «Список N». Чтобы добавить язык, достаточно поля
`name_<язык>`. Предмет разрешается через `Game.GetFormFromFile(id, plugin)`, отсутствующий
плагин даёт `None` и предмет пропускается (DLC не обязательны, как в AutoMedic и SCCM).
В список попадают только `Weapon` с типом граната или мина. Всё прочее пропускается и
пишется в лог. Одиннадцатый и дальнейшие списки отбрасываются.

## 4. Устройство

**esp** (генерируется `tools/gen_esp.py` на основе `esp_writer.py` из SCCM и AutoMedic,
единственный мастер — `Fallout4.esm`):

- `EXC_Quest` (Start Game Enabled) со скриптом `EXC:CyclerQuest`, в нём вся логика.
- Алиас игрока `EXC_PlayerAlias` со скриптом `EXC:PlayerAlias`: события инвентаря и
  перезагрузки.
- `EXC_List01..10` (FLST): рабочие списки, заполняются из JSON в рантайме
  (`Revert` + `AddForm`), порядок = порядок в файле.
- `EXC_AllExplosives` (FLST): объединение всех списков, фильтр для
  `AddInventoryEventFilter`.
- `EXC_CycleItem` (ALCH, вес 0, цена 0) + `EXC_CycleEffect` (MGEF, Script) со скриптом
  `EXC:CycleItemEffect`: вызывает `NextList()` и возвращает себя через
  `AddItem(self, 1, true)`. Приём тот же, что у `QS_OpenBarterAidEffectScript` в Quick Sell.
  Предмет можно положить в избранное (1–12).
- `EXC_Settings` — отдельный квест со свойствами MCM (приём AutoMedic: у
  `PropertyValue*` нет `scriptName`).

**Скрипты:**

- `LoadLists()` на `OnQuestInit`, на `OnPlayerLoadGame` и по кнопке MCM «Перечитать
  списки»: парсинг JSON → FLST, названия в `String[]`.
- `NextList()` / `PrevList()`: одна функция `StepList(±1)` ищет ближайший индекс с
  `GetItemCount(EXC_ListN) > 0`, затем `EquipFirst(n)`, затем уведомление.
- `NextItem()` / `PrevItem()`: одна функция `StepItem(±1)` в текущем списке ищет от
  позиции текущего предмета ближайший с `GetItemCount > 0` (по кругу), экипирует его,
  выводит уведомление. Если в списке, кроме текущего предмета, ничего нет, снова выводится
  уведомление с текущим.
- Во всех четырёх защита от повторного входа (флаг занятости), как в Quick Sell.
- `OnItemRemoved` у алиаса игрока (фильтр `EXC_AllExplosives`): если удалён текущий
  предмет и `GetItemCount(item) == 0`, вызывается `EquipNextInList()`. Короткий таймер
  (~0,3 с) даёт анимации броска закончиться, иначе новый `EquipItem` может её сорвать.
  Удаление из-за продажи, передачи или выбрасывания тоже засчитывается. Если предмет не был
  экипирован, ничего не делаем.
- `OnItemEquipped`: если игрок сам взял гранату или мину из какого-то списка, текущий
  предмет запоминается, а текущим становится первый список, где он есть (без уведомления).
- Экипировка: `Game.GetPlayer().EquipItem(item, false, true)`.
- Имя предмета: F4SE `Form.GetName()` (локализовано самой игрой). Для компиляции нужна
  заглушка F4SE-объявления, как `build/f4se_stubs` в AutoMedic.
- Лог — свой файл `Data\ExplosivesCycler\ExplosivesCycler.log` через GOEPE (как у AutoMedic),
  уровень задаётся в MCM.

**Зависимости:** F4SE, MCM, Garden of Eden Papyrus Extender (чтение JSON и лог). DLC не
требуются.

## 5. MCM и локализация

Страница «Настройки»:
- четыре клавиши (`keybinds.json`, `CallFunction`): «Следующий список» → `NextList`,
  «Предыдущий список» → `PrevList`, «Следующий предмет в текущем списке» → `NextItem`,
  «Предыдущий предмет в текущем списке» → `PrevItem`;
- «Брать следующий предмет, когда кончился текущий» (вкл.);
- «Показывать уведомления» (вкл.);
- кнопка «Перечитать списки» с подсказкой, какой файл используется (default или user) и
  сколько списков загружено;
- уровень лога.

Переводы: `Interface\Translations\ExplosivesCycler_en.txt` / `_ru.txt` (UTF-16 LE с BOM,
TAB), все `text`/`help` — токены `$EXC_…`. Строки уведомлений из скрипта («Нет
взрывчатки…», «X: закончились»): сначала проверить, переводит ли
`Debug.Notification("$EXC_…")` токен через те же файлы. Если нет, короткая таблица строк в
скрипте по `sLanguage` (ru/en, иначе en). Имя предмета мода в esp: так же проверить `$`-токен
в `FULL`, иначе нейтральное «Explosives Cycler» на обоих языках.

**Состояние 2026-09-23:** шаги 1, 3, 4, 5 (раскладка) сделаны; мод разложен по игре,

отдельно: они вошли в протокол приёмки P1–P12 (README.ru.md), а подробный лог пишет всё,
что нужно для их разбора. T4 не нужна: уведомления переводятся таблицей в скрипте по
`sLanguage`, имя предмета мода — нейтральное «Explosives Cycler». Отличия от плана:
алиаса игрока нет (события — `RegisterForRemoteEvent` на квесте), настройки — ModSetting
MCM, а не квест `EXC_Settings`.

P10 (бросок из VATS) не проверялся. Первый прогон уронил загрузку сейва — строка кеша
~5 КБ в переменной скрипта (исправлено, см. комментарий у `LoadedLines`).

1. **Данные.** Досчитать урон «зачарованных» и составных гранат в `scan_explosives.py`
   (`ENCH` → `MGEF`, дочерние `PROJ` → `EXPL`), сверить с вики. Сгенерировать
   `lists-default.json` скриптом `tools/gen_lists.py` из `data/explosives.json`
   с правилами из §2.
2. **Проверки в игре (до основного кода)**, на минимальном тестовом скрипте:
   - T1: `EquipItem(граната)` кладёт её в слот гранаты и не снимает оружие в руках.
   - T2: при броске последней гранаты приходит `OnItemRemoved` (и/или `OnItemUnequipped`)
     с `akDestContainer == None`, в какой момент анимации.
   - T3: `EquipItem` сразу после броска не ломает анимацию (подобрать задержку).
   - T4: `Debug.Notification("$TOKEN")` и `$` в `FULL` предмета: переводятся ли.
   - T5: `GetEquippedWeapon(n)`: каким индексом отдаётся экипированная граната (если

4. **MCM:** `config.json`, `keybinds.json`, переводы.
5. **Развёртывание и приёмка:** `tools/deploy.py` (esp → `Data\`, `.pex` →

   гранату на следующую и будет спорить с этим модом. Протокол приёмки:

   - клавиши «следующий/предыдущий предмет»: перебор по кругу внутри списка, пропуск

## 7. Решения пользователя (2026-09-23)

- Капканы и шипы Far Harbor в списки мин не включаются.
- Кончился текущий список → сообщение «X: закончились» и остановка, без перехода на
  другой список.
- Кроме «Следующего списка» в MCM есть клавиши «Предыдущий список», «Следующий предмет в
  текущем списке», «Предыдущий предмет в текущем списке».

- Подобранная граната или мина **сама экипируется**, если ничего не экипировано и она есть
  в текущем списке (`OnItemAdded`, уведомление «X, Y»).
- Уведомление — «Предмет (метка)», метки списков «–» (слабые) и «+» (мощные), у коктейля
  Молотова метки нет (пустое название). Стрелок и ▲ в шрифте уведомлений нет.
- Уведомления отстают (очередь HUD) — выбор показывается своей строкой на экране (SWF-виджет
  в HUDMenu), в MCM: способ показа, время до скрытия (0 — всегда), X/Y в %, выравнивание,
  шрифт, цвет.
- Количество: «Осколочная граната ×8 (–)» (MCM, вкл.), в строке обновляется после каждого
  броска и подбора.
