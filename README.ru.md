# Explosives Cycler — «Переключатель взрывчатки»

Мод для Fallout 4 (1.10.163, F4SE). Гранаты и мины собраны в списки (до 10), списки лежат
в JSON. Клавиши MCM или предмет «Explosives Cycler» во вкладке «Помощь» переключают
списки и предметы по кругу, на экране — значки списка и предмет, например
«[значок гранаты][значок гранаты] Разделяющаяся осколочная граната ×5». Когда экипированная граната
или мина кончается, берётся следующая из того же списка.

## Что делает

| Действие | Результат |
|---|---|
| «Следующий список» (клавиша или предмет) | следующий список, в котором что-то есть; экипируется его первый имеющийся предмет |
| «Предыдущий список» | то же в обратную сторону |
| «Следующий / предыдущий предмет в текущем списке» | следующий / предыдущий имеющийся предмет текущего списка, по кругу |
| брошен последний предмет | следующий имеющийся предмет того же списка; список пуст — «[значок] Предмет: список пуст», и всё |
| подобран предмет текущего списка, а для броска ничего не экипировано | он экипируется |

Пустые списки при переключении пропускаются. Если пусто везде — «Нет взрывчатки из
списков».

Выбор показывается **строкой на экране** (по умолчанию) и/или уведомлениями — MCM,
раздел «Строка на экране». Строка меняется сразу при каждом нажатии (уведомления игры идут
очередью и отстают), скрывается через заданное время (0 — не скрывается и всегда
показывает текущий предмет). Там же — положение X/Y в процентах экрана, выравнивание,
размер шрифта и цвет (по умолчанию — цвет HUD из настроек игры). По умолчанию строка
стоит в левом нижнем углу (X 1 %, Y 95,5 %, по левому краю, шрифт 22) и не скрывается. Новое положение видно
после выхода из меню.

«Показывать количество» (вкл. по умолчанию) добавляет число экипированной взрывчатки в
инвентаре: «[значок] Осколочная граната ×8». Число в строке обновляется после каждого броска и
подбора этого предмета (уведомлений на броски нет).

## Списки

`Data\ExplosivesCycler\lists-default.json` идёт с модом и обновлением перезаписывается.
Свои списки — в `lists-user.json` рядом (скопировать стандартный и править): если он
есть, стандартный не читается совсем. После правки — MCM → «Перечитать списки».

Правила формата (файл разбирается построчно): одна пара ключ-значение на строке,
один предмет на строке, предмет — `"Плагин.esm|ЛокальныйHexID"`. Название списка —
`name_<язык>` по `sLanguage` из `Fallout4.ini`, иначе `name_en`. Предметы из
неустановленных плагинов (DLC) пропускаются. Больше 10 списков — лишние отбрасываются.

Стандартные списки (урон считает `tools/scan_explosives.py`: взрыв + урон зачарования +
дочерние заряды):

1. `[grenade]` — гранаты по возрастанию урона (слабые первыми), без коктейля Молотова.
2. `[grenade][grenade]` — гранаты по убыванию урона (мощные первыми).
3. `[mine]` — мины по возрастанию урона.
4. `[mine][mine]` — мины по убыванию урона.
5. `[molotov]` — коктейль Молотова.

Название списка стоит перед именем предмета, без скобок. Метки `[grenade]`, `[mine]`,
`[molotov]` (строчными) строка на экране рисует значками цвета текста: граната и мина —
ванильные значки счётчика взрывчатки HUD, молотов нарисован в том же стиле (в игре его
нет). Метки можно смешивать с текстом. Уведомления игры значков не умеют — там метки
просто убираются. Для текста в названии: стрелок и `▲` в шрифте игры нет (проверено по
`fonts_en.swf`), годятся `+ - – — • · × » « № / |`, буквы и цифры.

Не входят: служебные гранаты (маяки, шашки, «ГаллюциГен», «Ярость», «Хищник»,
«Убеждение», «Кроличья лапка»), капканы и шипы Far Harbor.

## Требования

F4SE (со скриптами: мод зовёт `Form.GetName()`), MCM, Garden of Eden Papyrus Extender.
DLC не нужны.

## Устройство

- `ExplosivesCycler.esp` (единственный мастер — `Fallout4.esm`): квест `EXC_Quest`
  (`0x800`, скрипт `EXC:CyclerQuest`), списки `EXC_List01..10` + `EXC_AllExplosives`
  (FLST, наполняются из JSON), предмет `EXC_CycleItem` + эффект `EXC_CycleEffect`
  (скрипт `EXC:CycleItemEffect`).
- Скрипт квеста ловит события инвентаря игрока (`OnItemRemoved`, `OnItemUnequipped`,
  `OnItemEquipped`, `OnItemAdded`) через `RegisterForRemoteEvent` с фильтром
  `EXC_AllExplosives`. Отслеживается только тот предмет, который экипирован через мод или
  взят игроком из списков (`CurItem`).
- JSON разбирается один раз: в сейве запоминаются язык, имя файла и его строки (построчно —
  строка длиннее ~4 КБ в переменной скрипта ломает загрузку сейва); совпали — списки
  берутся из сейва.
- Настройки — ModSetting MCM (`Data\MCM\Settings\ExplosivesCycler.ini`); перечитываются
  при запуске, по внешнему событию MCM `OnMCMSettingChange|ExplosivesCycler` и при
  закрытии меню паузы.
- Строка на экране — `Interface\ExplosivesCycler.swf` (класс `EXCWidget`, исходник
  `widget/EXCWidget.as`): грузится F4SE `UI.Load` в `root1` HUDMenu, текст —
  `UI.Invoke(SetText)`, положение и видимость — `UI.Set`. Сцена HUD — 1280x720.
  Метки значков виджет разбирает сам: текст идёт отдельными TextField, значки —
  векторные фигуры (`Graphics`), всё в одну строку. Контуры значков — блок `ICONS` в
  `EXCWidget.as`, его пишет `tools/gen_icons.py`: гранату и мину берёт из `HUDMenu.swf`
  (`RightMeters_mc.ExplosiveAmmoCount_mc.TypeIcon_mc`, фигуры 329 и 408), молотов
  описан в самом скрипте.
- Лог — `Data\ExplosivesCycler\ExplosivesCycler.log` (прошлая сессия —
  `ExplosivesCycler.1.log`), уровень в MCM.

## Сборка

```
python tools/scan_explosives.py        # data/explosives.json из esm игры
python tools/gen_lists.py              # mod/ExplosivesCycler/lists-default.json
python tools/gen_mcm.py                # mod/MCM/..., mod/Interface/Translations/...
python tools/gen_esp.py                # build/ExplosivesCycler.esp
python tools/gen_icons.py              # значки в widget/EXCWidget.as (нужны Java, FFDEC_JAR, игра); только если меняются значки
python tools/gen_widget.py             # mod/Interface/ExplosivesCycler.swf (нужны Java и FFDEC_JAR)
"<игра>\Papyrus Compiler\PapyrusCompiler.exe" papyrus ^
    -i="papyrus;build\f4se\Source;<игра>\Data\Scripts\Source\User;<игра>\Data\Scripts\Source\Base" ^
    -o="build\scripts" -f="Institute_Papyrus_Flags.flg" -all
python tools/deploy.py                 # в игру, оба Plugins.txt
```

`build\f4se\` — содержимое `Data\Scripts` из `f4se_0_06_23.7z`
(f4se.silverlock.org/archive): `Source\*.psc` нужны компилятору (объявление
`Form.GetName`), `Form.pex` кладёт в игру `deploy.py`, если там ванильный. В
`Data\Scripts\Source\User` должны быть `MCM.psc` и `GardenOfEden*.psc`.

`gen_widget.py`: Flash-редактора нет — скрипт собирает SWF-заготовку с пустым классом
(ABC-байткод руками) и компилирует в неё `widget/EXCWidget.as` через JPEXS FFDec
(`-importScript`, github.com/jindrapetrik/jpexs-decompiler, zip; `playerglobal.swc` в
комплекте). `FFDEC_JAR` — путь к `ffdec-cli.jar`.

`deploy.py --esh-off` / `--esh-on` убирает / возвращает Explosives Swap Hotkeys: он тоже
меняет кончившуюся гранату и будет спорить с этим модом.

## Проверка в игре

Перед проверкой: MCM → Explosives Cycler → назначить 4 клавиши, «Лог» = «Подробный».
Взрывчатку — консолью (`player.additem <ID> 5`): осколочная граната `0EEBED`,
бейсбольная `107BD6`, криогенная `0FF21D`, коктейль Молотова `10C3C6`, осколочная мина
`0E56C2`, криомина `10C669`.

| # | Что сделать | Ожидается |
|---|---|---|
| P1 | Загрузить сейв | в «Помощи» есть Explosives Cycler; в логе «списки загружены … 5 шт.» |
| P2 | «Следующий список» несколько раз | «[граната] Граната из бейсбольного мяча ×5» → «[мина] Осколочная мина ×5»… по кругу; у мощных — два значка, у Молотова — значок молотова; значки цвета строки, по высоте вровень с текстом, пустые пропущены; граната реально экипирована, оружие в руках не снято |
| P3 | «Предыдущий список» | тот же круг назад |
| P4 | «Следующий / предыдущий предмет» в «Слабых гранатах» | бейсбольная ↔ криогенная ↔ осколочная по кругу, список не меняется |
| P5 | Использовать предмет Explosives Cycler из Pip-Boy | как «Следующий список», предмет остался в инвентаре |
| P6 | Бросить все бейсбольные гранаты | после последней: «[граната] Криогенная граната ×5», она экипирована; анимация броска не сорвана |
| P7 | Выбросить всё из списка «Коктейль Молотова» броском | «[молотов] Бутылка с коктейлем Молотова: список пуст», ничего не экипировано |
| P8 | После P7 `player.additem 10C3C6 3` | коктейль экипируется сам, «[молотов] Бутылка с коктейлем Молотова ×3» |
| P9 | Мины: то же, что P6 | следующая мина из списка |
| P10 | Бросок из VATS, в силовой броне | как P6 |
| P11 | Скопировать lists-default.json в lists-user.json, переименовать список, MCM → «Перечитать» | новое название в строке; `[mine]` посреди текста — значок на месте метки |
| P13 | MCM → «Способ показа» = уведомления | «Осколочная граната ×5» без меток `[grenade]` и без пробела в начале |
| P12 | Сохранить, загрузить | всё работает, в логе «списки не изменились» |

Для разбора — `Data\ExplosivesCycler\ExplosivesCycler.log`: строки `OnItemRemoved`,
`OnItemUnequipped` (что приходит при броске последнего), `OnItemEquipped … GetEquippedWeapon
0/1/2/3` (каким индексом движок отдаёт гранату). Ошибки скриптов — только в
`Papyrus.0.log` (нужны логи Papyrus в ini).
